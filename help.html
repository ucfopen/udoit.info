Help & FAQs

We understand UDOIT can be a learning curve, but we’re here to help. Here are some of our main questions and issues encountered while using UDOIT. This may also include upcoming features, enhancements, and fixes.

What is an accessibility barrier?

In online course content like in Canvas, an accessibility barrier occurs when things are created in such a way that certain users cannot access the same information or experiences that other users can.

One example is having subtitles, captions, or transcripts alongside digital videos. Without captions, most users can simply watch the video, but some users-- those with hearing impediments-- will not be able to access the same information. Captions provide them an equivalent experience.

Another example is attaching alternative text descriptions to images. When images contain important information, they should be clearly described in text form. That way, users who cannot see the image, whether for physical or technical reasons, can still understand what the image is trying to convey.

Most accessibility barriers are invisible to content creators, and require tools like UDOIT to help find and address them.

Who does UDOIT help?

Accessibility barriers that UDOIT can detect and help resolve don't only affect users with disabilities. Creating accessible content can benefit all users. Consider the following examples:

  • Ensuring high contrast between colors benefits:
    • Those with vision impairments or low vision
    • Those in less-than-ideal circumstances, like poor lighting or outside on mobile devices
  • Adding alternative text to images benefits:
    • Those dependent on screen readers
    • Users with insufficient network bandwidth where images fail to load
  • Ensuring that all links contain self-descriptive text benefits:
    • Those dependent on screen readers
    • Those with cognitive disabilities or difficulty understanding
    • Those with motor disabilities or who rely on keyboards to navigate
    • All users who use links to navigate
What is the difference between an "issue" and "potential issue" in UDOIT?

The UDOIT scanner is often able to definitively identify accessibility issues. For example, a computer can decide whether two colors have sufficient contrast or whether an HTML table has been formatted correctly.

But often, accessibility rules are conditional. For example, headings must be formatted in a specific way, but the scanner can't tell whether any particular text is intended to be a header or is just a short paragraph.

When UDOIT identifies a "potential issue," it will require some user input to determine what, if anything, needs to be done.

What sorts of accessibility barriers does UDOIT find and help me resolve?

UDOIT finds a wide range of issues, and can detect most barriers listed in the Web Content Accessibilty Guidelines. Specific barriers include:

  • HTML Element has an Incompatible ARIA Role
  • IDs Must Be Referenced Correctly
  • Images Should Have Alternative Text
  • Information Should Not be Conveyed by Color Alone
  • Instructions Should Not Rely on Shape, Size, or Location
  • Interactive and Landmark Areas Should Have Labels
  • Labels Should Be Unique
  • Languages Should be Specified Correctly
  • Links Should Contain Descriptive Text
  • Lists Should Have Proper List Markup
  • Media Should Have Captions and Transcripts
  • Tables Should Have Descriptive Captions
  • Tables with Data Should Have Headers
  • Text Must Have Sufficient Color Contrast with the Background
Where does UDOIT fit alongside other accessibility tools like Canvas Accessibility Checker?

There are many different tools available to help improve online accessibility. Each tool has strengths and weaknesses, and are designed for different use cases.

Tool Where to Use When to Use
Accessibility Checker Widget Within Canvas on the "Edit" page Every time you create or edit a page
In-app Accessibility Tools Within other apps, like Word or PowerPoint Before saving or exporting a file
UDOIT Within Canvas as an app plugin Before publishing an entire course, between semesters, or when course-wide reporting data is needed
